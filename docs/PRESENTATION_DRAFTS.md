# Perspective Ads プレゼンテーション構成案

今回のプロジェクトの背景にある「詳細な分析」と「熱い想い」を活かすための、3つのプレゼン構成案を提案します。

---

## パターンA（詳細版）：【王道・ストーリー型】「景色」を「体験」に変える物語
**コンセプト**: あなたの原体験と課題意識から入り、聴衆の共感を呼んでからデモで驚かせる構成。
**ターゲット**: 一般聴衆、デザイナー、エモーショナルな審査員

### プレゼンテーション構成（スライド別台本）

#### 1. 導入 (Hook)
**スライド**: 街中に溢れるが、誰も見ていないサイネージや広告の写真（ボカシを入れるなど）
**台本**:
「皆さん、直近で外に出た時のことを思い出してください。」
「その時、通り過ぎたいくつの広告を覚えていますか？」
「おそらく、一つも思い出せないのではないでしょうか。」
「現代人にとって、広告はもはや情報ではなく、ただの無視すべき『景色』になってしまいました。」

#### 2. 課題 (Problem)
**スライド**: YouTubeのスキップボタン、スマホを見ながら歩く人々
**台本**:
「YouTube広告は5秒でスキップされます。街中のサイネージは視界にすら入りません。」
「どれほど美しい映像を作っても、ユーザーが『見よう』と思わない限り、その情報は届かないのです。」
「私たちは、広告に対して極めて受動的になってしまいました。」

#### 3. 解決策のヒント (Insight)
**スライド**: マクドナルドの「叫ぶ広告」のイメージ画像、またはAISASモデル図（Attention → Action）
**台本**:
「しかし、ある広告だけは例外でした。マクドナルドの『叫ぶ広告』です。」
「画面に向かって叫ぶとクーポンがもらえる。たったそれだけの仕掛けに、人々は行列を作り、熱狂しました。」
「なぜか？ それは、『叫ぶ』という**能動的なアクション**が、無視という壁を粉砕したからです。」

#### 4. アイデア (Idea)
**スライド**: 「叫ぶ」→「？」、覗き込むシルエット
**台本**:
「私たちは考えました。これを、もっと日常的な動作で、もっとスマートに実現できないか？」
「『叫ぶ』のはハードルが高い。でも、つい『覗き込みたくなる』ものならどうでしょう？」
「見るのではなく、自ら探しに行く体験。それが私たちの答えです。」

#### 5. プロダクト紹介 (Product)
**スライド**: 製品ロゴ『Perspective Ads』、キャッチコピー「視線で、世界を動かせ。」
**台本**:
「そこで開発したのが、覗き込む裸眼VR広告。『Perspective Ads』です。」

#### 6. デモンストレーション (Demo)
**スライド**: （実演、またはデモ動画）
**台本**:
「論より証拠。実際に見ていただきましょう。」
（デモ開始：画面の前で体を左右に動かす）
「私が右に動くと…画面の中の景色も回り込みます。左に動けば、向こう側が見えます。」
「まるで、そこに箱庭が存在しているかのような感覚。」
「そして、深く覗き込むと…（QRコード発見）あ！こんなところにクーポンが隠れていました！」

#### 7. 仕組み (Technology)
**スライド**: 構成図（Webカメラ → Python/MediaPipe → WebSocket → Three.js/WebGL）
**台本**:
「特殊なメガネは一切不要です。」
「WebカメラがPythonでユーザーの顔と視線をリアルタイムに追跡し、計算された角度を瞬時にThree.jsへ送信することで、この没入感を実現しています。」
「0.1秒の遅延もなく追従するこの『気持ちよさ』に、徹底的にこだわりました。」

#### 8. 提供価値 (Value)
**スライド**: AISASモデルの再構築図（ActionがStart地点）
**台本**:
「これは単なる面白映像ではありません。」
「『覗き込む』という身体的アクションをトリガーにすることで、AISASモデルにおける『Interest（興味）』と『Action（行動）』を強制的に引き出します。」
「受動的な『景色』を、能動的な『エンターテインメント』へ変える装置なのです。」

#### 9. 結び (Closing)
**スライド**: プロダクトロゴと未来の展望（多くの人が覗き込んでいるイメージ）
**台本**:
「広告はもう、邪魔なものではありません。自ら探しに行く宝探しです。」
「Perspective Adsで、広告の未来を書き換えます。」
「ご清聴ありがとうございました。」

## パターンB：【戦略・ハッカソンハック型】賞を獲るための論理的アプローチ
**特徴**: 冒頭で「分析」を提示し、「勝つためにこれを作った」という戦略性をアピールする構成。
**ターゲット**: エンジニア、技術選定を重視する審査員、分析好きな人

1.  **【宣言 (Declaration)】: 最優秀賞を獲りに来ました**
    *   「私たちは今回、本気で勝ちに来ました。そのために、過去56チームの受賞作品を徹底分析しました。」
2.  **【分析 (Analysis)】: 勝てる作品の条件**
    *   「優秀賞は『機能』。努力賞は『工夫』。では最優秀賞は何か？」
    *   「答えは『体験の変革』と『常識の書き換え』でした。」
    *   「単に便利なツールを作るのではなく、ユーザーの行動そのものを変える必要があります。」
3.  **【戦略 (Strategy)】: AISASモデルのハック**
    *   「現代のマーケティング課題であるAISASモデルの停滞。これを打破するのは『身体性』です。」
    *   「私たちは『覗き込む』という動作をトリガーに、強制的にInterestとActionを引き出します。」
4.  **【デモ (Demo)】: 論理の実証**
    *   「論理だけではありません。実装を見てください。」
    *   （デモ: スムーズな追従、隠し要素の発見）
    *   「Pythonの顔認識とWebGLの描画を低遅延で同期させることで、この体験を実現しました。」
5.  **【展望 (Future)】: 広告の未来**
    *   属性分析によるターゲティング機能にも言及。
6.  **【結び (Closing)】**
    *   「既存のサイネージの『中身』を変えるだけで、世界は変わります。これが私たちの出した『最優秀賞』への回答です。」

## パターンC：【技術・UX型】「覗く」という行為の発明
**特徴**: 技術的な実装と、それによって生まれるUX（ユーザー体験）の面白さにフォーカスする構成。
**ターゲット**: UXリサーチャー、プログラマー、ギークな層

1.  **【問いかけ (Question)】: 画面の向こう側**
    *   「画面の裏側、見たことありますか？」
    *   「二次元のディスプレイに、三次元の奥行きを与える。それが今日のテーマです。」
2.  **【コンセプト (Concept)】: 裸眼VR体験**
    *   特殊なメガネはいらない。必要なのは「あなたの体」だけ。
    *   プロジェクト名『Perspective Ads』。
3.  **【技術構成 (Tech Stack)】: Python × Three.js**
    *   ここを厚めに語る。
    *   ユーザーの微細な動きをMediaPipeで検知 → 座標変換 → WebSocket → Three.jsでカメラ制御。
    *   没入感を削がないための「低遅延」へのこだわり。
4.  **【UXの設計 (UX Design)】: アフォーダンス**
    *   「ただ映像が流れているだけでは人は動きません。」
    *   「少し揺らす」「視線が合う」ことで違和感を与え、自然と「覗き込みたくなる」仕掛け（アフォーダンス）を作りました。
5.  **【デモ & シナリオ (Demo)】**
    *   通行人が足を止める → 違和感 → 覗き込む → クーポン発見！という一連の流れを披露。
6.  **【結び (Closing)】**
    *   「技術の力で、ディスプレイの物理的な制約を超えました。」
    *   「次は、街中のサイネージをすべてこれに変えてみたいです。」
