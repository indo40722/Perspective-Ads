# Perspective Ads 要件定義書

## 1. プロジェクト概要
**プロジェクト名**: Perspective Ads  
**コンセプト**: 「受動的な『景色』としての広告」を、「自らのぞき込んで発見する『エンターテインメント』」へ再定義する。  
**ターゲット**: 広告を無視することに慣れてしまった現代の若者、通行人。  
**アピールポイント**: 
特殊なデバイス（VRゴーグル等）を装着することなく、裸眼で、身体的な動作（覗き込み）を通じて画面内の世界とインタラクションするUX。

---

## 2. 目的とゴール (ハッカソン戦略)
### コンセプト：A+B ハイブリッド（Ordinary Ad comes alive）
本プロジェクトは、以下の2つのアプローチを統合します。

1.  **Plan A（3D空間重視）**: 「覗き込む」と奥行きが出る没入感。
2.  **Plan B（実用性重視）**: 一見ただのポスターだが、隠し要素（クーポン）がある。

**コア体験（UXフロー）**:
`「ただのポスターかと思った（油断）」→「近づいたら奥行きが出た（驚き）」→「覗き込んだらクーポン見つけた（報酬）」`

### 2.1 戦略的要件（機能要件）
- **通常モード（2D Poster Mode）**:
  - ユーザーが遠い、または検知されていない状態。
  - 平面的な広告画像（ポスター）として表示。視差効果は最小限またはゼロ。
- **没入モードへの遷移（Transition to 3D）**:
  - ユーザーが接近（Z距離 < 閾値）すると、スムーズに3D空間情報が付加される（Z深度の有効化）。
  - クーポンなどの重要情報は、障害物（3Dオブジェクト）の裏側に隠蔽され、初期状態では視認不可とする。
- **発見モード（Finding Hidden Objects）**:
  - ユーザーが大きく頭を傾ける（角度 > 閾値）ことで、障害物の死角にあるクーポンを発見できる。

### 最優秀賞（体験の変革）へのアプローチ
- **「見る」から「覗く」へ**: 既存のデジタルサイネージの常識（平面的な映像を一方的に流す）を覆し、ユーザーの頭の動きに連動して視差（Parallax）を生み出すことで、画面の向こうに実在する箱庭があるような錯覚を与える。
- **AISASモデルの身体的再構築**: 「叫ぶ」の代わりに「覗き込む」という動作をトリガーにし、AttentionからActionまでの転換率を劇的に高める。

### 優秀賞（技術力）へのアプローチ
- **Python × MediaPipe/OpenCV**: 高速かつ高精度な顔認識・視線追跡の実装。
- **Three.js (WebGL)**: リアルタイムな3Dレンダリングと、バックエンドからの座標データに応じたカメラワークの同期。
- **属性推定（オプション）**: 年齢・性別推定によるコンテンツの出し分け（ターゲティング）。

## 3. システム構成 (Architecture)

### 3.1 ハードウェア構成
- **ディスプレイ**: 一般的なPCモニター、またはサイネージ用ディスプレイ。
- **カメラ**: Webカメラ（ユーザーの顔・視線をトラッキング）。

### 3.2 ソフトウェア構成図
```mermaid
graph LR
    User[ユーザー] -- 映像 --> Camera[Webカメラ]
    Camera -- 映像データ --> Py[Backend (Python)]
    subgraph "Backend (Python)"
        Face[顔検知・特徴点抽出 (MediaPipe/OpenCV)]
        Calc[座標・角度計算]
        Attr[属性推定 (Age/Gender)]
        SocketServer[WebSocket Server]
    end
    Py -- JSON (X, Y, Z, Angle, Attr) --> SocketClient[WebSocket Client]
    subgraph "Frontend (Web/Three.js)"
        SocketClient -- 座標データ --> 3DScene[Three.js Scene]
        3DScene -- レンダリング --> Display[ディスプレイ]
    end
    User -- 視覚情報 --> Display
    User -- 覗き込み動作 --> Camera
```

## 4. 機能要件 (Functional Requirements)

### 4.1 センシング・解析機能 (Backend / Python)
1.  **リアルタイム顔検出**: Webカメラ映像から通行人の顔を検出する。
2.  **3次元位置推定**: カメラから見た顔の相対位置（X, Y, 距離Z）および顔の回転角度（Yaw, Pitch, Roll）を算出する。
3.  **属性推定**: 検出した顔から、大まかな「年齢層」「性別」を推定する（ターゲット選定トリガー）。
4.  **WebSocket送信**: 解析したデータを低遅延でフロントエンドへ送信する。

### 4.2 演出・描画機能 (Frontend / Three.js)
1.  **視差レンダリング (Off-Axis Projection的な挙動)**:
    - ユーザーが右に動けば、画面内のカメラを左に移動（または被写体を回転）させ、側面が見えるようにする。
    - ユーザーが近づけば、中を覗き込むように視野角（FOV）やカメラ位置を調整する。
2.  **インタラクティブ・コンテンツ**:
    - 通常時は2Dポスター風、または待機モーション。
    - 視線検知時に「箱」が開く、または商品が飛び出すアニメーション。
    - 死角（覗き込まないと見えない位置）へのオブジェクト配置。
3.  **リワード表示**:
    - 特定の角度まで覗き込んだこと（閾値判定）を検知した場合、隠されたQRコードやクーポンを表示する。

---

## 5. 非機能要件 (Non-Functional Requirements)
1.  **パフォーマンス**: ユーザーの動きと画面の反応の「遅延（レイテンシ）」を極小化する。遅延が大きいと「自分の視点と動いている」感覚が損なわれるため。
2.  **UX/UI**: 初見のユーザーでも「動けば画面が変わる」ことが直感的にわかるような、導入のアフォダンス（誘目性）を持たせる。
3.  **環境耐性**: 会場の照明や背景のノイズに影響されにくい強固なトラッキング設定。

---

## 6. 使用技術スタック (Tech Stack)
- **Backend**: Python 3.x
    - ライブラリ: OpenCV, MediaPipe (またはdlib), FastAPI/Flask (サーバー), python-socketio (通信)
- **Frontend**: JavaScript/TypeScript
    - ライブラリ: Three.js (またはReact Three Fiber), Socket.io-client
- **Hardware**: Webカメラ付きPC (ラップトップ可)
