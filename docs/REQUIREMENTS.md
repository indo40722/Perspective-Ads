# Perspective Ads 要件・実装方針

## 1. 作品概要

Perspective Adsは、デジタルサイネージ広告を「見るもの」から「身体を動かして探すもの」へ変えることを目指すプロトタイプです。

Webカメラでユーザーの顔位置を取得し、その位置に応じて画面内の3Dシーンの見え方を変化させます。正面からは見えない報酬を、左右へ覗き込むことで発見する体験を核にします。

## 2. 現在のPoC

### Backend

実装済み：

- OpenCVでWebカメラ映像を取得
- MediaPipe Face Meshで1人の顔を検出
- 鼻先ランドマークを基準に相対的なX / Y / Z値を取得
- 顔検出の有無を判定
- Socket.IOで約30FPSを目安にフロントエンドへ送信

注意：

- 現在のZ値はMediaPipeランドマークの相対値であり、実空間上の距離そのものではない
- Yaw / Pitch / Rollの算出は未実装
- 複数人追跡は未実装

### Frontend

実装済み：

- Three.jsによる3Dシーン
- 顔の左右移動に応じた仮想カメラ移動
- Deadzone
- 非線形な入力感度
- Lerpによる簡易平滑化
- 2Dポスター表現
- ポスターの奥に隠した疑似クーポン
- 大きく左右へ移動すると裏側を覗けるPoC

注意：

- 現在は本格的なOff-Axis Projectionではない
- `camera.position` + `lookAt()` とポスター回転を組み合わせた簡易的な視差表現
- 画面の物理サイズやカメラ位置に基づくキャリブレーションは未実装

## 3. 技育展2026で優先する要件

### 3.1 視点連動投影

最優先。

目標：

- ディスプレイの物理幅・高さを設定できる
- カメラとディスプレイの相対位置を設定できる
- ユーザー視点位置を画面座標系へ変換できる
- ユーザー視点に応じて非対称視錐台を計算する
- Three.jsのprojection matrixへ反映する

これにより、現在の「カメラを大きく左右に動かして錯視を強調する」方式から、実際の視点位置と画面の関係に基づく投影へ改善する。

### 3.2 トラッキング安定化

目標：

- 生のランドマーク座標の揺れを抑える
- 静止時は細かなジッタを抑え、移動時は遅れすぎない
- 顔を一時的に見失った際の復帰を自然にする
- 異常な座標ジャンプを抑制する

候補：

- Exponential Moving Average
- One Euro Filter
- 移動速度に応じた適応的スムージング

### 3.3 キャリブレーション

目標：

- 使用する画面サイズを設定できる
- カメラの取り付け位置を設定できる
- 初期視点位置を基準化できる
- 異なるPC・モニターでも再現しやすくする

### 3.4 報酬発見フロー

目標：

1. 正面では通常広告として見える
2. 身体を動かすと奥行きが感じられる
3. 覗くことで隠れた報酬を発見できる
4. 発見後に取得可能なQRなどを提示する

重要：

「斜めのQRを直接読ませる」こと自体は目的ではない。
中心価値は、報酬を空間的に隠すことでユーザーに探索行動を起こしてもらうこと。
