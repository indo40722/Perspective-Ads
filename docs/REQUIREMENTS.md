# Perspective Ads 要件・実装方針

## 1. 作品概要

Perspective Adsは、デジタルサイネージ広告を「見るもの」から「身体を動かして探すもの」へ変えることを目指すプロトタイプです。

Webカメラでユーザーの顔位置を取得し、その位置に応じて画面内の3Dシーンの見え方を変化させます。正面からは見えない報酬を、左右へ覗き込むことで発見する体験を核にします。

## 2. 現在のPoC

### Backend

実装済み：

- OpenCVでWebカメラ映像を取得
- MediaPipe Face Meshで1人の顔を検出
- 鼻先ランドマークから正規化座標を取得
- 顔検出の有無を判定
- 640×480を要求してカメラ処理
- WindowsではDirectShow、Media Foundationの順にカメラを開き、映像を取得できるまで再試行
- カメラの起動・利用可能・利用不可状態をSocket.IOでフロントエンドへ配信
- 新しいフレームだけをフレーム番号付きでSocket.IO送信
- 顔を見失った状態と、フレーム更新停止を検出

注意：

- 現在のZ値はMediaPipeランドマークの相対値であり、実空間上の距離そのものではない
- Yaw / Pitch / Rollの算出は未実装
- 複数人追跡は未実装
- カメラ利用不可時のブラウザ表示と、顔未検出状態の区別を実装

### Frontend

実装済み：

- Reactによる画面・操作状態の管理
- Viteでビルドした静的フロントエンド
- Three.jsによる3Dシーン
- 起動時に顔位置を15フレーム取得し、中央値を左右移動の基準として設定
- 基準位置からの左右移動だけを視点位置へ反映
- 上下方向は追跡せず、投影上もY=0に固定
- ブラウザの縦横比にかかわらず、3D表示領域は16:9を保って中央に配置
- ソフトDeadzoneとOne Euro Filterによる適応的な入力平滑化
- 経過時間に基づく描画補間
- `projection.js` によるOff-Axis Projection補助処理
- 画面寸法と概算視点位置から非対称視錐台を計算し、Three.jsのprojection matrixへ反映
- 広告背景・商品ビジュアル・特典を異なる奥行きに配置した3D広告シーン
- 正面では一つのバーガーとして表示し、視点が左右の発見閾値に達すると、上バンズ・トマト・レタス・チーズ・カツ・下バンズの6具材層を上下・左右・奥行きへ最大分離
- SketchfabのGLBで独立しているトマト3枚とゴマを該当層へまとめ、皿・旗・棒を商品表示から除外
- 正面へ戻るとモデルの各ノードを滑らかに組み戻す
- モデルの表示領域に合わせて大きさと中心位置を自動調整
- バーガーのPBR素材に合わせた暖色のキーライトと控えめな補助光
- 発見した具材名と味の説明を、商品下部に3Dラベルとして表示
- 深夜限定バーガーの広告コピー、価格、3D商品ビジュアル、発見後のクーポン表示を統一したビジュアル
- 商品の死角に置いた疑似クーポンと、視点移動に反応してほどける具材層
- 左へ覗いて炭火焼きパティ、右へ覗いて熟成チェダーをそれぞれ発見する探索フロー
- 左右の発見後に正面へ戻るとバーガーが完成し、クーポンが現れる報酬フロー
- 発見中の進捗表示、層の分離と3D味ラベル、再挑戦操作
- デバッグ表示中に左右キーとSpaceで探索フローを確認できる入力
- 発見後の報酬オーバーレイ

注意：

- Off-Axis Projectionは初期実装段階であり、ディスプレイ寸法・カメラFOV・視点距離は概算値を使っている
- MediaPipeのランドマーク `z` は実距離そのものではないため、現在の投影計算では固定距離を使っている
- 初期視点位置は自動で基準化するが、実ディスプレイ寸法・カメラ位置・視点距離を合わせる物理キャリブレーションは未実装
- 16:9以外の画面では表示領域の外側に余白ができる
- カメラが640×480に対応しない場合は、実際の取得解像度が異なることがある
- 現行モデルはSketchfabの「Burger by Juzeone」。1KテクスチャのGLBで、上バンズ・ゴマ・トマト・レタス・チーズ・カツ・下バンズが別オブジェクト。具材ごとに6層へまとめ、皿・旗・棒を隠す。CC BY 4.0のため、READMEに作者名と作品名のクレジットを記載
- Innerscene 3D Parts Libraryの「Burger with fries」はCC0だが、実画面で低ポリゴン感が強かったため現行モデルには採用しない
- Sketchfabの「Realistic Burger」は比較候補として評価済み。GLB 2.0、画像テクスチャ9枚、6ノードを確認したが、具材名とメッシュの対応が粗いため現行モデルには採用しない
- 正面ではモデルの基準位置へ戻り、左右へ覗くと各具材層がファン状に開く。発見閾値に達した時点で最大分離になる。どの発見でどの具材が主役になるかの演出と質感調整は継続課題
- クーポンは現時点では疑似表示

## 3. 技育展2026で優先する要件

### 3.1 視点連動投影

最優先。

目標：

- ディスプレイの物理幅・高さを設定できる
- カメラとディスプレイの相対位置を設定できる
- ユーザー視点位置を画面座標系へ変換できる
- ユーザー視点に応じて非対称視錐台を計算する
- Three.jsのprojection matrixへ反映する

これにより、現在の「カメラを大きく左右に動かして錯視を強調する」方式から、実際の視点位置と画面の関係に基づく投影へ改善する。

現在の状態：

- 初期実装済み
- 安定した顔位置15フレームの中央値を基準に、左右の相対移動を概算視点位置へ変換している
- カメラから届く新しいフレームだけを処理し、描画側は経過時間で補間している
- 上下移動は利用しない
- 非対称視錐台をThree.jsのprojection matrixへ反映している
- キャリブレーションと実距離推定は未完成

### 3.2 トラッキング安定化

目標：

- 生のランドマーク座標の揺れを抑える
- 静止時は細かなジッタを抑え、移動時は遅れすぎない
- 顔を一時的に見失った際の復帰を自然にする
- 異常な座標ジャンプを抑制する

現状：

- One Euro Filterを使い、入力速度に応じて平滑化を調整
- 描画側の補間係数をフレーム間の経過時間から計算
- 顔を見失ったときは視点を中央へ滑らかに戻す

### 3.3 キャリブレーション

目標：

- 使用する画面サイズを設定できる
- カメラの取り付け位置を設定できる
- 初期視点位置を基準化できる
- 異なるPC・モニターでも再現しやすくする

現在の状態：

- 初回の顔検出時に、安定した15フレームから左右の基準位置を自動設定
- `C`キーで基準位置を取り直せる
- 画面サイズ・カメラ位置・実視点距離の物理キャリブレーションは未実装

### 3.4 報酬発見フロー

目標：

1. 正面では通常広告と、左右に隠れた2つの味の手掛かりが見える
2. 左右へ覗き込むとOff-Axis Projectionで視差が生まれる
3. 左右それぞれで一定時間覗き、炭火焼きパティと熟成チェダーを発見する
4. 2つを見つけたあと正面へ戻るとバーガーが完成する
5. 完成後にクーポンを提示する

重要：

「斜めのQRを直接読ませる」こと自体は目的ではない。
中心価値は、視点移動を単なるクーポン表示のスイッチにせず、商品に結び付いた2つの発見と完成の行動にすること。

## 5. 技術的なチャレンジとして残す記録

開発中は、単に完成コードだけでなく以下を残す。

- 初期実装で何が不自然だったか
- どの投影方式を試したか
- トラッキングの揺れや遅延がどの程度あったか
- どのフィルタ・パラメータが効いたか
- キャリブレーション前後で何が変わったか
- 正面から報酬が見えてしまう問題をどう解いたか

技育展2026の「技術的なチャレンジ・工夫」を説明するため、失敗と改善の履歴も成果として扱う。
