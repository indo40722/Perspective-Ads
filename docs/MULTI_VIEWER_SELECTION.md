# 複数人対応（探索行動による参加者ロック）

対象ブランチ: `feat/multi-viewer-intent-lock`（`codex/supabase-vercel-integration` から作成）

## 目的

公共サイネージの前に複数人がいるとき、顔検出の信頼度が高い人へ勝手に切り替わるのではなく、**最初に探索行動を行った人**の動きを一時的に採用する。ほかの人が通り過ぎても広告を急に切り替えない。

これは「視線推定」「顔認証」「誰が本当に広告に興味を持ったかの識別」ではない。顔の位置と大きさを使った匿名の、短時間の操作権選択である。

## アルゴリズム（初期値・実機調整前）

1. MediaPipe Face Detector の検出結果を最大8人分、画像を送信せずブラウザ内で処理する。
2. 顔中心・顔の相対サイズ・移動予測を用いてフレーム間で匿名の一時IDを対応づける。
3. 200ms以上追跡できた人の、初回位置からの横移動（正規化座標で0.075以上）または顔の見かけの大きさの1.10倍以上を参加候補とする。
4. 移動後に180ms程度安定した最初の候補をロックする。同時の候補は、120ms以内の差なら選択を保留する。
5. ロック中はほかの顔で表示を操作しない。一時遮蔽は1.5秒まで保持する。
6. ほかの顔と重なって同一人物か分からなくなった場合は、勝手に操作権を渡さず画面操作を保留し、選び直す。
7. 離脱後は広告と抽選セッションを初期化する。ただしQRを表示済みなら、スマホで読み取るため約6秒の表示猶予を設ける。

## 実装箇所

- `frontend/src/faceTrackingWorker.js`: 顔を1人に絞らず複数返す。
- `frontend/src/viewerSelection.js`: 純粋な追跡・参加判定・選択固定ロジック。
- `frontend/src/browserFaceTracker.js`: 選択された顔だけをReactの広告側へ送る。
- `frontend/src/App.jsx`: 参加前の位置を基準に広告を動かす。QR表示時間と次の参加者への状態リセットを管理。
- `frontend/src/viewerSelection.test.js`: Node.jsで再現可能なシミュレーションテスト。

## テスト

```bash
npm --prefix frontend test
npm --prefix frontend run build
```

### 決勝に向けて実機で追加確認すること

- 1人だけで左右移動・接近した場合、最初の動きが広告に反映されるか。
- 3人で静止した場合、勝手に選ばれないか。
- 1人の操作中にほかの2人が通過しても、画面が切り替わらないか。
- 2人が顔の位置を交差させた場合、安全に操作を保留できるか。
- 参加者がスマホを掲げて顔が隠れた場合、QRを読み取る猶予があるか。
- 表示画面とカメラ位置が離れている、低照度、マスク、身長差、見切れ、多人数の場合に問題がないか。
- 1〜2時間の連続起動でメモリ・フレームレート・切断後復帰に問題がないか。

## 未解決・限界

- 人物の外観を使うReIDは行わないため、顔の完全な交差や長い遮蔽を越えて同一人物を保証できない。位置追跡が曖昧なときは誤操作を避けるためにロック解除を優先する。
- 歩きながら一瞬止まる人を参加者として誤判定する可能性がある。実機で閾値を計測して調整する。
- 同じ場所で複数人が同時に参加するとロックが成立しないことがある（仕様上の保留）。
- 本変更は `VITE_FACE_TRACKING_SOURCE=browser` のブラウザ顔追跡モード向け。Python/FastAPIのローカル顔検出系は未変更。
- QRの不正取得・発行数制限・抽選と発行の一貫性は**別のセキュリティ課題**であり、本変更で解決したわけではない。
- 実機での操作検証と本番公開環境へのデプロイは未実施。閾値は仮設定。
