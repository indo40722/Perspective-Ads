# Perspective Ads ユースケース定義書

## 1. アクター (Actors)
- **ユーザー（通行人）**: 広告の前を通りかかる人。特定のアプリ等のインストールは不要（裸眼で体験）。
- **システム**: Webカメラとディスプレイを備えたサイネージシステム。

---

## 2. メイン・ユースケース (Main Scenarios)

### UC-01: 通行人の注意を引く (Attention)
**トリガー**: ユーザーがシステムの近く（例: 半径2m以内）を通行する。
1.  **システム**はカメラ映像から人物を検知する。
2.  **システム**は人物の属性（例: 若者）を推定し、ターゲットであると判定する。
3.  **システム**は画面内の3Dオブジェクト（例: ハンバーガー）を、ユーザーの顔の動きに合わせて微妙に揺らし、「ただの映像ではない」という違和感を与える。
4.  **ユーザー**は「画面の中の物体が自分を見ている（反応している）」ことに気づき、足を止める。

### UC-02: 覗き込みインタラクション (Interest / Search / Action)
**トリガー**: ユーザーが画面に対して興味を持ち、顔を動かす。
1.  **ユーザー**が「横から見たらどうなるんだろう？」と疑問を持ち、頭を左右に動かしたり、画面に顔を近づけたりする。
2.  **システム**は頭の位置（X, Y, Z座標）をリアルタイムに追跡する。
3.  **システム**は3D空間のカメラアングルを同期させ、ユーザーの視点移動に合わせて「向こう側の世界」を描画する。
    - *演出例*: 正面からは見えなかったハンバーガーの裏側の具材が見える。箱の側面が見える。
4.  **ユーザー**は自分の身体的動作と映像が完全に同期する没入感（裸眼VR体験）を楽しむ。

### UC-03: 発見と報酬 (Share)
**トリガー**: ユーザーが特定の角度（死角）まで大きく覗き込む。
1.  **ユーザー**が、正面からは障害物に隠れて見えなかった「隠し要素（QRコード付きのクーポンチケット）」を見つけようと、大きく首を傾ける。
2.  **システム**はユーザーの顔の位置が「発見可能エリア」に達したことを検知する。
3.  **システム**は隠されていたQRコードを明確に表示し、エフェクト（パーティクル等）で発見を祝福する。
4.  **ユーザー**は自身のスマホを取り出し、QRコードを撮影する。
5.  （任意）**ユーザー**はその体験（必死に画面を覗き込む自分と、得られた報酬）をSNS等でシェアする。

## 3. AISASモデルとの対応表

| 段階 | ユーザーの心理・行動 | Perspective Ads の機能・演出 |
| :--- | :--- | :--- |
| **Attention** (認知) | 街中の景色に「違和感」を感じる。 | 通行人の顔に合わせて、画面内の物体が視線を送る・微動する。 |
| **Interest** (興味) | 「自分の動きに反応している？」と興味を持つ。 | 顔を動かすと、リアルタイムでパース（遠近感）が変化する。 |
| **Search** (検索) | 仕組みを理解し、隠された情報を探そうとする。 | オブジェクトの裏側や、箱の奥を覗き込もうとするアフォーダンス提示。 |
| **Action** (行動) | 身体を動かして覗き込み、QRコードを取得する。 | 覗き込み検知 × 隠しQRコードの表示。 |
| **Share** (共有) | 面白い体験として誰かに伝えたくなる。 | 能動的な「発見」の喜びを提供。 |

## 4. 例外・代替フロー (Alternative Flows)

### 複数人検知の場合
- **シナリオ**: 複数の人がカメラの範囲に入った場合。
- **システム動作**:
    - カメラに最も近い（Z座標が小さい）、または画面中央に近い人物を「メインターゲット」としてロックオンする。
    - 他の人物には反応しない、あるいはターゲット以外にはボカシを入れるなどの処理を行う。

### トラッキングロストの場合
- **シナリオ**: ユーザーが急に動いたり、カメラの範囲外に出たりして顔を見失った場合。
- **システム動作**:
    - 3Dモデルをゆっくりと「正面位置（デフォルト）」に戻す。
    - 画面に「Look Here!」などのアイコンを表示し、再度カメラを見るよう促す。
