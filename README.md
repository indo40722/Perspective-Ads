# Perspective Ads

**広告の前で、一歩動く。商品を知り、特典に出会う。**

駅などの公共空間にある縦型デジタルサイネージを想定した試作です。正面ではステーキの写真だけが見えます。左へ動くと、手前のステーキが右へずれ、背景に隠れていた小さなQRと短い案内が写真の端から現れます。割引額やコードはサイネージには出さず、QRをスマートフォンで読んだ後、受取操作をすると一回限りのデモコードを発行します。店側のデモ画面でコードを一度だけ利用済みにでき、QR表示・受取・利用確認の件数を見られます。右へ動くと断面写真に切り替わります。

## 体験

- 正面：商品写真と広告コピーを表示
- 左：手前のステーキが右へずれ、奥に隠れた小さなQRと「見つけた方へ」の案内が現れる
- 右：断面写真と火入れの説明へ切り替わる
- 左へ動き続ける：商品写真と奥の情報の重なり方が変わり、QRが読み取れる範囲まで現れる。割引額とコードはスマートフォンで開いた後に表示
- QRをスマートフォンで読む：特典の受取画面を開く
- 「デモ特典を受け取る」：この受取キー用のコードを発行
- 店側の利用確認画面：コードを入力して一度だけ利用済みにする
- 店側の集計：QRページ表示、特典受取、利用確認の件数を表示
- 「最初に戻す」：写真と特典の状態をリセット

商品画像はコンセプト素材です。受取画面で発行するコードはデモ用で、実在の店舗、商品、注文、決済、割引とは連携していません。発行記録と集計値はバックエンドのSQLiteデータベースに保存します。氏名や連絡先などの個人情報は取得しません。

## 想定する画面

主用途は縦型9:16のサイネージです。商品写真は画面上部、広告コピーは下部に置きます。QRはコピーの下へ追加せず、写真と同じ画面領域にある奥のレイヤーとして重ねます。サイネージには小さなQRと案内だけを出し、特典の内容は読み取り後にスマートフォンで表示します。横長のPC画面にも対応しますが、動作確認用です。

## 起動方法

### カメラなしで試す

Node.js 20.19以降を用意し、プロジェクトのフォルダーでPowerShellを開きます。

```powershell
npm --prefix frontend install
npm --prefix frontend run dev -- --host 127.0.0.1
```

表示されたURL（通常は`http://127.0.0.1:5173/`）をブラウザーで開きます。画面を左右にドラッグすると、焼き目と断面の見せ方が変わります。

Viteだけでは広告画面の表示確認までです。QRページの受取・利用確認を試すときは、FastAPIバックエンドも起動してください。カメラを使わず両方を試す場合は別のPowerShellで次を実行し、その後にViteのURLを開きます。

```powershell
$env:PERSPECTIVE_CAMERA_ENABLED = "0"
py -3.10 backend/main.py
```

### カメラを使う

Windows、Python 3.10、Node.js 20.19以降、Webカメラが必要です。初回のみPythonの依存関係を入れます。

```powershell
py -3.10 -m pip install -r backend/requirements.txt
```

バックエンドを起動します。

```powershell
.\start_backend.bat
```

ブラウザーで[http://127.0.0.1:8000/view/index.html](http://127.0.0.1:8000/view/index.html)を開きます。終了時は起動したコンソールで`Ctrl+C`を押してください。バックエンド起動中はカメラを使用します。

フロントエンドのテストとビルド：

```powershell
npm --prefix frontend test
npm --prefix frontend run build
```

### スマートフォンでQRを試す

同じWi-FiにつないだスマートフォンからQRを開く場合、サイネージ画面も`127.0.0.1`ではなくPCのローカルIPアドレスで開きます。`127.0.0.1`は読み取ったスマートフォン自身を指すためです。Windowsでは`ipconfig`でPCのIPv4アドレスを確認し、PCとスマートフォンの両方から到達できる`http://<PCのIPv4アドレス>:8000/view/`を使います。ネットワークやファイアウォールの設定により接続できない場合があります。

スマートフォンでQRを読み、受取ボタンを押します。店側画面はPCで`http://127.0.0.1:8000/view/redeem.html`を開き、スマートフォンに出たコードを入力します。初回は利用確認が記録され、同じコードをもう一度入力すると利用済みとして拒否されます。実際の値引きは発生しません。

公開環境では、ビルド前にQRの遷移先を設定します。

```powershell
$env:VITE_COUPON_URL = "https://公開ホスト/view/coupon.html"
npm --prefix frontend run build
```

公開ホストには`coupon.html`も配置してください。QRコードは正面では商品写真に隠れ、左へ動いて奥の情報が見えると読み取れます。

特典ページとAPIは同じホストから配信してください。静的サイトなど別のホストへ分ける場合は、APIの公開先設定と許可するアクセス元の設定が別途必要です。

## 操作

| 操作 | 動作 |
| --- | --- |
| 顔を左右へ動かす | 写真広告の見どころを切り替える |
| 画面を左右にドラッグ | カメラを使わず見どころを切り替える |
| 特典解放後にQRを読む | スマートフォンで特典の受取画面を開く |
| スマートフォンの「デモ特典を受け取る」 | 個別の一回限りデモコードを発行する |
| 店側の利用確認画面 | 初回だけコードを利用済みにし、各段階の件数を表示する |
| 「最初に戻す」 | 商品写真と特典の状態を初期状態へ戻す |
| `D` | 視点座標と接続状態を表示 |
| `←` / `→` / `Space`（`D`表示中） | 視点入力を確認する |
| `R` | 最初に戻す |
| `F` | 全画面表示を切り替える |

## 技術と素材

- ReactとCSSで写真レイヤー、広告コピー、特典の表示状態を管理
- QRコードからスマートフォン向けデモ特典ページへ接続
- OpenCV、MediaPipe Face Mesh、FastAPI、Socket.IOで顔の左右位置を取得
- 正面写真の寄りと断面写真の切り替えで、商品詳細を見せ分ける
- 広告主の許諾を得た商品写真・特典へ差し替えられる構成を目指す

写真に写っていない面を3Dで再現する試作ではありません。実運用へ進む場合は、広告主から利用許諾を得た商品写真、コピー、特典条件へ差し替えます。

## 検証したいこと

静止広告と比べて、自発的な視点移動が生まれるか。動いた人は商品名や焼き目・火入れを覚えているか。クーポンが商品より目立っていないか。少人数でこの3点を確かめます。滞在時間だけから広告効果や日次利用を結論づけません。
